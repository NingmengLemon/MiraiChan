# mikufans 链接与卡片解析

群里出现 mikufans 的短链或小程序卡片时, 自动跟一次重定向, 去掉跟踪参数, 回一条干净链接。
装上可选的  SDK 之后, 额外启用更多功能。

## 指令

没有指令, 自动响应。发一条含短链或小程序卡片的消息即可。

## 两种能力

| 能力 | 条件 |
| --- | --- |
| 短链重定向 + 卡片链接抽取 + 去跟踪参数 | 默认开启, 纯 aiohttp, 不依赖任何私有包 |
| 视频标题 / UP 主 / 播放量摘要 | 需要 SDK `citric-mikufans` |

默认行为的细节:

- 卡片只认旧实现用过的两个字段: `meta.detail_1.qqdocurl` 与 `meta.news.jumpUrl`, 取不到就不动。
- 正文里的短链也会处理 (旧实现只处理卡片), 由 `rewrite_text_links` 控制。
- 查询参数按**白名单**保留: 每种资源路径只留下登记过的参数 (视频是 `p`/`t`, 搜索是 `keyword`/`page` 等), 其余一律丢弃, 上游新长出来的跟踪参数不需要跟。
- 一条消息里卡片与正文指向同一地址时只解析一次; 解析结果没变化就不回, 避免复读。

## 可选私有 SDK

`citric-mikufans` 在私有仓库里, 不写进依赖: 公开仓库保持可构建, 私有包由实例自己装:

```
uv pip install "citric-mikufans @ git+<your_repo>"
```

装好之后重启 bot, 日志里不会再出现"详情 SDK 不在"。没装时插件退化成只净化链接。

注意 `uv sync` 会把不在锁文件里的包当成多余项删掉, 所以部署时跑过 `uv sync --all-packages --frozen`
之后要重装一次私有 SDK; 或者用 `uv sync --inexact` 保留它。这一点写在部署 runbook 里。

SDK 的导入、传输层创建、字段读取都按"可选"处理: 缺包、原生依赖加载失败、接口漂移都只让详情降级,
默认的链接净化不受影响。

## 配置

`configs/mikufans/default.json`:

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| `max_items` | 1 | 一条消息最多解析几个链接, 范围 1..3 |
| `timeout` | 10.0 | 跟随重定向的超时 (秒) |
| `rewrite_text_links` | true | 正文里直接出现的短链也净化 |
| `enabled_groups` | 空 | 只在这些群生效, 留空表示不限制 |

配置项越界会让插件初始化失败并记一条异常日志, 此时插件不响应; 改回合法值重启即可。

## 命名

代码、注释与文档里一律用 mikufans 代称这个站点; `links.py` 里的域名常量只用于识别链接。
